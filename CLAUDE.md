## What this is
A portrait mobile puzzle + world-restoration game (iOS/Android). Developer: SCYDE.
Rotate stone channels so water reaches dry saplings; each solved puzzle
restores part of an isometric island. Plays offline; progress is copied to SCYDE's cloud save
server (`server/luma-cloud`) with optional Apple/Google/Facebook sign-in. No monetization yet.

## Architecture rules
- Puzzle rules are pure `RefCounted` classes (`scripts/puzzle`, `scripts/water`) — testable without
  scenes. One connectivity model (`Dir` bit masks N=1,E=2,S=4,W=8) for game, solver, validator, tests.
- A puzzle is solved when `WaterSimulation` says so — never when an animation ends.
- Progress is saved **at the moment of solving** (`Game.complete_level`), before any animation.
- Rewards are idempotent (`ProgressionModel`): replays never re-grant one-time rewards; restoration
  stages only move forward; essence never negative.
- Views (`TileView`, `BoardView`, `IslandView`) only draw and emit input; they never mutate rules state
  except through the screen that owns them.
- Levels are JSON data (`resources/levels`), validated by the real solver in CI. Never ship a level
  the solver cannot prove solvable (or that has an unachievable optional objective).
- All player text goes through `tr()` / `UI.t()` with keys in `resources/localization/strings.csv`.
- No colour-only signals: rotatable = round disc with notches, fixed = square with rivets,
  gate links = colour **and** shape.
- Art is procedural (`scripts/ui/painter.gd`); audio/icons are generated by scripts in `tools/`.
  Every file in `assets/` must be listed in `assets/ASSET_MANIFEST.json` with source + licence.
- Autoloads: `Analytics`, `Audio`, `Game` (state/save), `Router` (scenes), `Cloud` (cloud save,
  `scripts/cloud/`; off in headless runs). Tests set `Router.dry_run`; cloud tests use `Cloud.use_for_tests`.
- Cloud save (D-021): server `server/luma-cloud` (Node + MariaDB, admin dashboard at `/admin`,
  `npm test` with a local MariaDB); never overwrite a cloud save silently — a conflict asks the player.
- Sign-in (`plugins/luma_auth`): one "LumaAuth" singleton contract (`scripts/cloud/native_auth.gd`) for
  the Android v2 plugin (Kotlin) and the iOS GDExtension (Obj-C++); client ids only in
  `resources/cloud/cloud_config.json`; the Android preset uses the Gradle build.
- Merge mode (after level 30): rules in `scripts/merge/merge_game.gd` (pure, clock passed in as
  `now`), content in `resources/merge/*.json`, state in `save["merge"]`; see `docs/MERGE_DESIGN.md`.
- Islands 2–6 (`docs/ISLANDS_PLAN.md`): registry `resources/islands/islands.json`, progress in
  `save["islands"]`, unlocked by café tasks. Ember Reef rules in `scripts/slide/`, Lantern Bay in `scripts/light/`,
  Stone Steps in `scripts/push/`, Rope Isles in `scripts/bridges/`,
  Moon Grove in `scripts/match/`;
  an island's level screen is its `scene` in `islands.json`.

## Git workflow
- Branches: `main` (stable), `feature/*`, `fix/*`, `release/*`. Small descriptive commits.
- Never force-push shared branches. Never commit `build/`, `.godot/`, `android/`, keystores, certs.
- Run `tools/run_tests.sh` before pushing; CI must stay green.

## Security
- Signing material only via GitHub Actions secrets (names in `docs/RELEASE_RUNBOOK.md`). Never echo them.
- Analytics are local-only and whitelisted (`scripts/analytics/analytics_manager.gd`); no personal data.
- The app requests only `VIBRATE` and `INTERNET` on Android; CI fails on any other permission.
- The server stores only sign-in provider user ids, never e-mails/names; its env file
  (`/etc/luma-cloud.env`, Facebook app secret, DB and admin passwords) never goes into the repo.
